## Generation issues

These occur after passages have been selected: the model chooses what to say, preserves or drops details, and completes its response. Q_S1:7 also has a separate retrieval issue, documented below; the two observations do not establish that one caused the other.

### 1. Correct evidence is available, but the answer selects management instead of signs

Q_S1:5 is the clearest answer-generation failure. The reference asks for young-infant danger signs. The answer instead describes airway support, oxygen, ventilation, antibiotics, and glucose checks.

Packed source S2 contains the explicit checklist for infants under two months: inability to suck/feed, respiratory rate above 60, respiratory rate below 20 or periods of apnoea, severe indrawing, central cyanosis, and very cold arms/legs. The answer cites S1 and selects management content rather than reproducing the relevant checklist.

Therefore, finding more passages alone will not solve this case. The question's generic “correct action or answer” framing may encourage management advice, but the system still needs to preserve the underlying requested fact.

**Improve:** make the generator identify the answer type first—signs, threshold, action, or definition—and answer that type directly. For a signs question, return the source checklist before considering any additional explanation. Avoid treatment additions unless requested.

### 2. Important qualifiers are lost during summarization

Q_S1:2 weakens the severe-dehydration wording by dropping its diarrhoea qualification. Q_S1:6 does not explicitly carry forward the infant age scope and apnoea alternative, although the packed checklist is available.

These are not simply missing-keyword retrieval problems. Relevant evidence can still become an incomplete answer during generation.

**Improve:** preserve age groups, conditions, numerical operators, units, and alternatives such as “or apnoea.” Validate these against the cited passage. Keep the answer short enough that added advice does not obscure the requested criteria.

### 3. Q_S1:7 is truncated, not an API-error case

Q_S1:7 has `incomplete_response`, finish reason `length`, and 1,024 recorded completion tokens, matching the configured output maximum. Its pipeline time is approximately 16.50 seconds; there is no recorded timeout or API error.

The provider also reports 1,224 reasoning tokens for this response—more than its 1,024 completion tokens. This inconsistency prevents a reliable calculation of how the completion budget was divided. Reasoning-budget pressure is plausible, but the exact accounting is not established by these fields.

**Improve:** investigate the Qwen response/usage behavior, then test a suitable output budget and supported reasoning settings on this failed case. Record the actual model and reasoning configuration in the run manifest. Do not assume that raising the limit fixes the separately observed evidence gap.

### 4. Citation checks are not support checks

The nine accepted answers pass citation validation while one still answers the wrong question and two lose qualifiers. Several answers add treatment, surveillance, or diagnostic claims beyond their benchmark targets.

**Improve:** check that the cited passage supports the requested answer and each consequential added claim. If the necessary rule is absent, explicitly abstain rather than constructing it from separately related passages.

## Retrieval issues

These concern which evidence reaches the generator. A missing rule in packed context establishes an evidence-selection gap, but does not by itself distinguish candidate-search failure from ranking or context-packing failure.

### 1. Unrelated passages reach the packed context

For Q_S1:7, the packed sources include clinic communication/history-taking, newborn asphyxia material, general fever discussion, and an outbreak press-release template. Some passages discuss fever or referral separately, but the explicit **fever plus inability to feed → admission/referral** rule is absent from the packed context.

**Improve:** inspect whether the exact supporting passage appears anywhere in each path's candidate pool. If present but ranked too low, test reranking or a relevance filter before packing context. If absent from both pools, improve clinical-intent query construction or candidate coverage. A reranker cannot recover a passage it never receives.

### 2. Evidence selection is sensitive to question formulation

Q_S1:8, a second formulation of the same topic as Q_S1:7, does retrieve the relevant wording in S6 and answers correctly. The underlying rule is available in the corpus, but does not consistently reach the generator.

**Improve:** compare both formulations' lexical and embedding candidates, fused ranks, and packed sources. Generic query processing should preserve the actual condition and requested relationship while reducing conversational framing. Do not remove words such as “clinic” globally: they may be clinically meaningful.

Both paths contribute to the final shortlist. An embedding candidate does not need to pass BM25 first, which addresses the concern that lexical mismatch could block semantic retrieval.

“Embedding-only” means absent from the lexical top-20 candidate list in this run—not that BM25 could never retrieve that passage at any depth. These counts measure contribution, not relevance or answer accuracy. The unrelated Q_S1:7 context shows that hybrid fusion still needs relevance evaluation.

## Recommended order of work

1. **Resolve incomplete generation:** reproduce Q_S1:7 with recorded model/budget settings; investigate usage accounting and test an appropriate generation budget. Independently check its missing evidence.
2. **Fix answer intent and qualifier preservation:** use Q_S1:5 and Q_S1:6 as regression cases; ensure signs questions produce complete, age-qualified checklists rather than treatment plans.
3. **Evaluate relevance before adding reranking:** inspect Q_S1:7 versus Q_S1:8 candidate pools. Rerank only if the required passage is available; otherwise improve query/candidate coverage. Reject unrelated administrative material before context packing.
4. **Add claim-support evaluation:** distinguish valid citation IDs from faithful use of their contents. Measure unsupported additions and appropriate abstention.
5. **Complete reporting exports:** run the notebook's final reporting/export cells for the existing checkpoint without unnecessarily regenerating answers.
6. **Run a controlled comparison:** evaluate BM25-only, embeddings-only, and hybrid over the same 100 questions with the same model, prompt, generation settings, and corpus. Measure supporting-passage recall, answer completeness, unsupported claims, truncation, latency, and cost separately. Test reranking as an additional controlled variant.

In simple terms: **keep both retrieval paths, make answers follow the requested question type, keep every important condition, filter unrelated evidence, and fix the output-limit failure.** This review changes documentation only; it does not change the system or rerun generation.
